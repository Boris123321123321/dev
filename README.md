# Эко-тиры: unit-экономика прогрессивных бонусов за утилизацию

Финансовая модель механики, в которой коэффициент начисления эко-бонусов за сдачу
вторсырья растёт вместе с валовой выручкой покупателя.

Результат сборки: `output/eco_tiers_unit_economics.xlsx`

## Что изменилось относительно предыдущей версии модели

| № | Требование | Как реализовано |
|---|---|---|
| 1 | Перевести расчёт на unit-экономику | Базовая единица — **один пользователь за один месяц** (лист `Unit-экономика`). Тиры и периоды получаются масштабированием юнита на число юзеров. |
| 2 | Убрать связку с АСР-сегментами ВВ, оставить границы выручки | Тир определяется **только** границей валовой выручки за календарный месяц: Старт < 3 000 ₽, Росток 3 000–12 000 ₽, Дерево 12 000–35 000 ₽, **Лес ≥ 35 000 ₽**. Сегменты остались только как справка на листе `Данные_бонусы`, в формулах не участвуют. |
| 3 | Считать в валовой выручке → грязная маржа | Все доходы идут от ВВ; грязная маржа = ВВ × ставка грязной маржи (`Допущения!B14`). |
| 4 | Учесть выгрузку фактической ВВ по пользователям с начала 2026 | Лист `Выручка_вход` — единственная точка входа по выручке. Пока выгрузки нет, там помеченный жёлтым плейсхолдер; приход файла = одна команда пересборки, формулы не меняются. |
| 5 | Разложить unit-экономику по каждому тиру и по периодам с 2026 года | Лист `Тир_Период`: блок на каждый тир × 12 месяцев 2026 года, отдельными строками доходы (ВВ, грязная маржа) и расходы (базовый бонус, бонус с механикой, доплата). |
| 6 | Убрать окна «90 дней» и «30 дней», перейти на месяцы | Квалификация в тир — за календарный месяц (`Допущения!B16`). Нормировка эмиссии — на число месяцев выгрузки, вычисляемое формулой из дат окна (`Допущения!B17`), вместо прежнего `×365/90`. |

## Листы книги

| Лист | Назначение |
|---|---|
| `Читать сначала` | Методика, что факт и что допущение, чего пока не хватает |
| `Допущения` | Границы тиров, множители, ставка грязной маржи, окна в месяцах, индексы |
| `Данные_бонусы` | Факт по выгрузке эко-бонусов + распределение начислений |
| `Выручка_вход` | Вход по валовой выручке: юзеров и ВВ/юзер по тирам × месяцам 2026 |
| `Unit-экономика` | Ядро: один пользователь за один месяц, по тирам |
| `Тир_Период` | Разложение по тирам × месяцам: доходы и расходы |
| `Миграция` | Unit-экономика одного перехода между тирами |
| `Сценарии` | Конверсии, годовой эффект, порог безубыточности |

Цветовая схема: серое — факт (не менять), жёлтое — допущения и ячейки под
заполнение, синий шрифт — введённое руками число, чёрный — формула, зелёный —
ссылка на другой лист.

## Данные

**Факт.** Выгрузка эко-бонусов `01.06.2025 — 31.07.2026`: 248 950 карт,
55 937 469 ₽ начислено за 14 месяцев → 3 995 533 ₽/мес → **16,05 ₽/юзер/мес**.

**Ещё не получено.** Фактическая валовая выручка по пользователям с начала
2026 года. Запрошена у аналитиков. До её прихода распределение по тирам на листе
`Выручка_вход` — плейсхолдер, помеченный жёлтым.

Сырая выгрузка содержит номера телефонов и **в репозиторий не коммитится**.
В git лежат только обезличенные агрегаты: `data/bonus_aggregates.json`.

## Сборка

```bash
pip install openpyxl pandas

# 1. Обезличить выгрузку бонусов → агрегаты без ПД
python3 scripts/aggregate_bonuses.py <выгрузка_бонусов.xlsx> \
    --start 2025-06-01 --end 2026-07-31 \
    -o data/bonus_aggregates.json

# 2. Собрать книгу
python3 scripts/build_model.py \
    --bonus-aggregates data/bonus_aggregates.json \
    -o output/eco_tiers_unit_economics.xlsx

# 3. Пересчитать формулы и проверить, что ошибок нет
#    (openpyxl пишет формулы без кэшированных значений — до пересчёта
#     любой ридер увидит в них пустоту)
soffice --headless --convert-to xlsx --outdir output/ output/eco_tiers_unit_economics.xlsx
```

Когда придёт выгрузка ВВ по пользователям — добавить `--revenue`:

```bash
python3 scripts/build_model.py \
    --bonus-aggregates data/bonus_aggregates.json \
    --revenue выгрузка_ВВ_2026.xlsx \
    -o output/eco_tiers_unit_economics.xlsx
```

Скрипт найдёт колонку с валовой выручкой (по имени: `ВВ`, `выручка`, `revenue`,
`gross`, `turnover`), разложит пользователей по границам тиров и посчитает
фактическую среднюю ВВ внутри каждого тира. Формулы книги при этом не меняются —
меняются только входные числа на листе `Выручка_вход`.

## Что выяснилось по ходу работы

**1. Связка «сегмент → тир» сильно завышала затраты механики.**
В прежней версии Амбассадор попадал в Лес (×2,85), Средний — в Дерево (×2,15).
Но по экономике самих сегментов из АСР-выгрузки средняя ВВ Амбассадора ≈
10 330 ₽/мес (5,0 покупок × 2 066 ₽) — до порога Леса в 35 000 ₽ он не доходит,
это уровень Ростка. Средний ≈ 1 212 ₽/мес — это Старт. Поэтому «слепая доплата»
в прежней версии (35,4 млн ₽/год) была следствием завышенного присвоения тиров.
По границам выручки в Лес попадают единицы процентов базы.

**2. Начисление эко-бонусов почти не зависит от покупательной силы.**
По АСР-сегментам, ₽/юзер/мес: Репертуарный 19,47 · Средний 18,10 ·
Амбассадор 12,20 · без сегмента 10,90. У Амбассадора начисление **ниже**, чем у
Репертуарного, монотонного тренда нет. Поэтому индекс базового бонуса по тирам
взят 1,00 для всех тиров (`Допущения`, раздел C) — это допущение с фактическим
основанием, а не догадка. Точную разбивку даст выгрузка бонусов в разрезе тиров.

**3. Распределение начислений крайне скошенное.**
Медиана 50 ₽ за 14 месяцев против средних 224,69 ₽; четверть карт получила
меньше 20 ₽. Множитель к почти нулевой базе почти ничего не стоит — риск
механики не в стоимости перехода, а в доплате тем, кто уже в высоком тире.

**4. Поля «Маржа ВВ/мес» прежней версии несовместимы с выручкой тех же сегментов.**
Для Репертуарного 376 ₽ маржи против 157 ₽ выручки (239 %), для Среднего
1 806 против 1 212 (149 %). Вывести ставку грязной маржи из них нельзя, поэтому
она задана отдельным допущением (`Допущения!B14`, по умолчанию 30 %) и
**требует подтверждения финансами**.

## Ограничения модели

- Ставка грязной маржи — допущение, не подтверждено.
- Распределение по тирам — плейсхолдер до прихода выгрузки ВВ по пользователям.
- Выгрузка бонусов даёт сумму за 14 месяцев на карту, а не по месяцам. Месячная
  эмиссия = среднее за окно × индекс месяца (индексы по умолчанию 1,00, то есть
  без сезонности). Разбивка начислений по месяцам даст здесь факт.
- Прирост маржи при переходе — разница средних ВВ тиров. Часть переходов
  случилась бы и без механики; реальную инкрементальность даст только A/B с
  holdout. Поэтому в модели три сценария конверсии и отдельно показан порог
  безубыточности.
